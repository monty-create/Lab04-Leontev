# Практическая работа №4. Процессор: ядра, потоки и нагрузка

## Цель работы
Изучить разницу между физическими ядрами и логическими процессорами, исследовать влияние многопоточности на общую загрузку CPU и отследить изменение частоты процессора под нагрузкой.

## Результаты исследований

### Шаг 2. Что видит программа
- **Логических процессоров (Environment.ProcessorCount):** 4
- **Архитектура процесса:** X64
- **64-битный процесс:** True

**Данные из Диспетчера задач (вкладка Производительность -> ЦП):**
- **Ядра:** 2
- **Логические процессоры:** 4
- **Базовая скорость:** 3.10 ГГц

**Вопрос:** Почему значение Environment.ProcessorCount нужно сравнивать с количеством логических процессоров, а не физических ядер?
**Ответ:** Потому что операционная система и среда выполнения .NET распределяют потоки программы по логическим ядрам (вычислительным потокам), которые видны системе как независимые процессоры.

### Шаг 5. Таблица загрузки CPU в зависимости от количества потоков

| Количество потоков | Примерная загрузка CPU (%) |
| :---: | :---: |
| 1 поток | ~ 25% |
| 2 потока | ~ 50% |
| 4 потока | ~ 100% |
| 8 потоков | ~ 100% |

**Вывод по таблице:**
Когда количество работающих потоков увеличивается, общая загрузка процессора растет линейно, пока не доходит до лимита логических процессоров (4 потока дают 100% нагрузки). Дальнейший рост потоков до 8 не поднимает нагрузку выше 100%, так как физические ресурсы чипа уже заняты полностью, и потоки просто делят время между собой.

### Шаг 6. Сравнение ядер и логических процессоров
- **Физические ядра:** 2
- **Логические процессоры:** 4

**Объяснение разницы:**
Количество логических процессоров больше физических ядер в 2 раза из-за технологии Hyper-Threading. Одно физическое ядро имеет дублирующие блоки и может обрабатывать два потока команд одновременно, поэтому система видит 4 ядра вместо 2.

### Шаг 7. Частота процессора
- **В простое (когда программа ничего не считает):** Частота сбрасывается до 1.60 — 2.00 ГГц для экономии энергии.
- **Под нагрузкой:** Частота сразу подскакивает до базовой (3.10 ГГц) или выше.

**Вывод:** Частота меняется динамически в реальном времени. Это сделано для экономии энергии и снижения нагрева в простое и для выдачи максимальной мощности, когда идут тяжелые вычисления.

## Итоговый вопрос (сравнение параметров 4 ядра и 8 процессоров)
У компьютера из примера 4 физических ядра и 8 логических процессоров. Программа сообщает Environment.ProcessorCount == 8. Здесь нет никакого противоречия, так как процессор поддерживает многопоточность (Hyper-Threading), и каждое из 4 физических ядер обрабатывает по два виртуальных потока, что дает операционной системе 8 независимых процессоров для работы.

## Ответы на контрольные вопросы

1. **Что показывает Environment.ProcessorCount?**
   Показывает число логических процессоров (вычислительных потоков), которые доступны операционной системе для распределения задач.
2. **Чем физическое ядро отличается от логического процессора?**
   Физическое ядро — это реальный кремниевый блок процессора на чипе. Логический процессор — это виртуальное ядро, созданное системой внутри одного физического ядра для параллельной работы.
3. **Почему увеличение количества потоков увеличивает загрузку CPU?**
   Потому что каждый новый поток загружает работой отдельное свободное логическое ядро. Больше занятых ядер — выше общий процент нагрузки в Диспетчере задач.
4. **Почему после некоторого количества потоков нагрузка перестает расти?**
   Потому что когда число потоков сравнивается с числом логических ядер процессора, ресурсы железа забиваются на 100%. Новой мощности взяться неоткуда, и потоки просто ждут своей очереди.
5. **Почему частота процессора может изменяться во время работы?**
   Из-за встроенных технологий энергосбережения и авторазгона. Процессор снижает частоту в простое, чтобы не греться, и поднимает ее до максимума при тяжелых циклах вычислений.

## Итоговый вывод
Мой компьютер имеет процессор с 2 физическими ядрами и 4 логическими потоками, что подтвердилось кодом и Диспетчером задач. Эксперимент наглядно показал, что один поток нагружает этот процессор максимум на 25% (1/4 от всей мощности), а для полной загрузки железа на 100% нужно запустить не менее 4 параллельных вычислительных потоков.
